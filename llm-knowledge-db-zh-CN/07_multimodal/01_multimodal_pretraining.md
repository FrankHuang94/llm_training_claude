# 多模态预训练（Multimodal Pretraining）

> **最后更新：** 2026-11-04
> **相关文件：** [视觉-语言模型](00_vision_language_models.md) · [跨模态对齐](02_cross_modal_alignment.md) · [数据收集与整理](../01_data/00_data_collection_and_curation.md) · [世界模型](../09_emerging_frontiers/02_world_models.md)
> **关键论文：** Jia et al. 2021 ALIGN（[arXiv:2102.05918](https://arxiv.org/abs/2102.05918)）· Schuhmann et al. 2022 LAION-5B（[arXiv:2210.08402](https://arxiv.org/abs/2210.08402)）· Google 2023 Gemini（[arXiv:2312.11805](https://arxiv.org/abs/2312.11805)）· Team Chameleon 2024 (early-fusion)（[arXiv:2405.09818](https://arxiv.org/abs/2405.09818)）· Assran et al. 2025 V-JEPA 2（[arXiv:2506.09985](https://arxiv.org/abs/2506.09985)）

## 概述
多模态预训练（multimodal pretraining）是模型首次大规模学习多种模态联合结构的阶段。大体有两种思路：**后期融合 / 连接器**方法，先预训练单模态编码器（CLIP 式）再把它们拼接起来（见 [VLM](00_vision_language_models.md)）；以及**早期融合 / 原生**方法，在**图文等交错的多模态 token 流上从零训练**单个 Transformer（Gemini、Chameleon）。向原生多模态预训练的转变——把图像、音频和视频都当作更多的 token——是 2024–2026 年最具决定性的架构趋势之一，使**任意到任意（any-to-any）**的理解与生成成为可能；到 2026 年，它已扩展到万亿参数级的开放 MoE（Kimi K3），以及报告无模态性能退化的全模态模型（Qwen3-Omni）。第三条非生成式路线——对视频进行**自监督潜在预测**（V-JEPA 2）——为规划和机器人学预训练感知能力。燃料是网络规模的配对数据（图文、视频-文本、音频-文本）以及海量无标注视频。

## 核心概念
**数据来源。**
- **图文：** **LAION-5B**（58 亿个经 CLIP 过滤的网络图文对——CLIP/扩散模型训练的开放支柱）、**ALIGN**（18 亿个带噪声的 alt 文本对，表明规模胜过重度清洗）、**CC12M**、**DataComp**、**COYO**。图文交错文档（MMC4、OBELICS）提供*文档级*的多模态上下文（对 Flamingo 式少样本学习至关重要）。
- **视频-文本：** WebVid、HowTo100M、InternVid；视频增加了**时间**维度和巨大的 token 数量。无标注的互联网视频（V-JEPA 2 使用了超过 100 万小时）可直接用于自监督目标。
- **音频：** 大型语音语料库（LibriSpeech、Common Voice）和网络音频；Whisper 使用了 68 万小时的弱标注网络音频。

**对非文本模态进行分词（tokenization）。** 要把一个模态送入 Transformer，就需要 *token*：
- **连续嵌入**（ViT 图块、音频编码器特征）通过连接器输入——保留信息，用于*理解*。
- 通过 **VQ-VAE / VQ-GAN / 分词器（tokenizer）**得到的**离散 token**（例如图像 → 码本索引，音频 → SoundStream/EnCodec 编码）——让模型能用同样的下一个 token 目标自回归地*生成*该模态（Chameleon、音频语言模型）。

**融合策略。**
- **后期融合（连接器）：** 独立编码器 + 投影/交叉注意力；模块化，复用强大的单模态预训练，更易构建。
- **早期融合（原生）：** 从一开始就用单个 Transformer 处理混合模态 token 序列（Gemini、Chameleon 的"混合模态早期融合"）。融合更紧密、可原生跨模态生成，但更难训练和稳定（模态间竞争、平衡问题）。

**目标函数。** 对比式（CLIP/ALIGN——对齐）、生成式/自回归（在多模态 token 上做下一个 token 预测——理解 + 生成）、掩码建模（BEiT/MAE）、**联合嵌入预测（JEPA）**——从可见上下文预测被掩码视频区域的*表示*，$\min \lVert g_\phi(f_\theta(x_{\text{ctx}}), m) - \bar f(x_{\text{tgt}})\rVert_1$，其中 $\bar f$ 为 EMA 目标编码器，从而避免像素重建——以及它们的组合。原生模型通常在交错 token 上使用**自回归**目标。

## 关键挑战
- **数据质量与对齐噪声。** 网络 alt 文本噪声大；过滤（CLIP 分数、去重（deduplication））必不可少但并不完美；高质量配对数据比文本更稀缺。
- **模态不平衡 / 干扰。** 各模态在 token 数、信息密度和难度上不同；朴素的联合训练会让某一模态占据主导，或造成负迁移（即对文本质量的"模态税"）。
- **token 爆炸。** 图像（高分辨率）尤其是视频会产生海量 token → 计算/上下文压力。
- **分词器质量（用于生成）。** 离散的视觉/音频分词器会丢失信息；重建质量决定了生成质量的上限。
- **训练稳定性。** 早期融合的多模态训练不如纯文本训练稳定（Chameleon 记录了特殊的归一化/初始化做法）。
- **发布版本分化。** 开放检查点可能缺少托管模型具备的某些模态，增加了复现难度。

## 解决方案与当前最佳实践
对于以*理解*为主的 VLM，**后期融合连接器**训练仍是实用的默认方案（更便宜、模块化，可利用 CLIP/SigLIP + 强 LLM）。**原生早期融合**是**任意到任意**模型（Gemini、GPT-4o）的前沿，如今也是旗舰开放 MoE 的前沿，依赖图文交错的多模态数据、精心的**模态平衡**和稳定性技巧（QK-norm、dropout、模态专属归一化）。**重度数据过滤**（CLIP 分数、去重、DataComp 式），并使用**图文交错文档数据**实现上下文内多模态能力。在需要跨模态*生成*时使用**离散分词器**（VQ/EnCodec）。质量分类器和合成字幕（用 VLM 重新生成字幕）能提升数据质量。对于具身/规划用途，**自监督视频预训练**加上少量动作条件后训练（V-JEPA 2-AC）的数据效率很高。

## 各实验室观点
- **Google DeepMind：** **Gemini** 从预训练起就是原生多模态的（文本/图像/音频/视频）——旗舰级早期融合模型；长上下文视频；**Veo 3** 为视频生成加入了原生音频（2025-05）；I/O 2026 上发布了"Gemini Omni"（细节未核实）。
- **OpenAI：** **GPT-4o** "omni"——跨文本/图像/音频的单一模型，具备原生生成能力（图像、语音）；CLIP/Whisper/DALL·E 一脉；**Sora 2**（2025-09）联合生成视频与音频。
- **Meta：** **Chameleon**（开放的早期融合混合模态模型）、ImageBind（绑定 6 种模态）、LLaMA 视觉、**V-JEPA 2**（自监督视频世界模型（world model））；闭源的 Muse Spark（2026-04）声称以低得多的算力实现强大的多模态理解（厂商声明）。
- **Qwen/阿里巴巴：** **Qwen3-Omni**（Thinker–Talker MoE）以及原生视觉-语言的 Qwen3.5；Qwen3.8 开放权重仅含文本。
- **其他开放实验室：** LAION（数据）、OpenCLIP、InternVL、Emu/Janus（统一理解+生成）；Kimi K3、DeepSeek V4.1-Flash、MiMo-V2.5 和 MiniMax M3 提供原生多模态。

## 最新进展（2023–2026年11月）
**原生任意到任意**模型（GPT-4o、Gemini）在一个 Transformer 中处理并*生成*多种模态。通过离散多模态 token 实现**统一理解 + 生成**（Chameleon、Emu3、Janus）。用 VLM 对网络图像**重新生成字幕**以提升数据质量（DALL·E 3、PixArt）。**视频**成为一等模态（长上下文 Gemini、视频分词器）。**音频原生**模型（实时语音、GPT-4o 语音）。围绕早期融合 vs 后期融合、以及统一模型采用离散还是连续表示的争论仍在继续。

**2025年中 → 2026年11月更新：**
- **V-JEPA 2（2025-06，arXiv:2506.09985）。** 在超过 100 万小时互联网视频上进行自监督 JEPA 预训练，在 Something-Something v2 上达到 77.3%；**V-JEPA 2-AC** 在不到 62 小时的无标注 DROID 机器人视频上后训练后，可通过在潜在空间中进行模型预测控制（MPC），零样本完成 Franka 机械臂的抓取放置——证明非生成式视频预训练只需极少动作数据即可迁移到控制。
- **Qwen3-Omni（2025-09，arXiv:2509.17765）。** 一个在文本、图像、音频和视频上联合训练的 30B-A3B Thinker–Talker MoE；作者报告相对单模态 Qwen 模型**没有模态性能退化**——这是对该规模下假定存在的"模态税"的一个反例。
- **联合音视频生成（2025-05 → 2025-09）。** Veo 3 引入了原生音频；Sora 2 生成同步的对白和音效，物理合理性也有所提升——预训练目标如今在样本层面耦合多种模态，而不仅仅是在共享嵌入空间中。
- **原生多模态扩展到万亿规模的开放 MoE（2026）。** Qwen3.5-397B-A17B（2026-02，原生视觉-语言，512 个专家）；MiMo-V2.5（2026-04，原生视觉+音频，1M 上下文）；MiniMax M3（约 2026-06，原生多模态，采用块稀疏注意力）；Kimi K3（2026-07，2.8T/104B，896 个专家中激活 16 个，原生视觉，1M 上下文）；DeepSeek V4.1-Flash（2026-09，552B，原生视觉）。混合/稀疏注意力让 1M token 上下文变得负担得起，这正是长篇交错多模态流得以实用的原因。
- **开放检查点与托管模型出现分化（2026-08）。** Qwen3.8-2.4T-A95B 的开放权重仅支持文本（始终开启思考），而托管的 Max-Preview 是多模态的——昂贵的多模态技术栈有时会被保留为专有。
- **效率主张改变了叙事框架。** Meta 声称 Muse Spark 以少得多的算力达到或超过 Llama 4 Maverick 级别的推理能力，并在多模态理解上最强（厂商声明）；Gemma 4 把文本/图像/音频预训练带到了 2B–4B 的端侧模型。

## 面试要点
> 💡 **实验室实际会问的问题：**
- **"早期融合 vs 后期融合——如何权衡？"** 原生联合训练（融合紧密、可任意到任意生成、更难/不稳定）vs 在预训练编码器上加连接器（模块化、更便宜、侧重理解）。
- **"如何把图像/音频输入 Transformer？"** 连续编码器特征（理解）或离散 VQ/EnCodec token（生成）。
- **"为什么 ALIGN/LAION 在噪声数据上依然奏效？"** 规模弥补了噪声（配合 CLIP 分数过滤）；对比学习对一定噪声具有鲁棒性。
- **"联合多模态预训练的主要挑战？"** 模态不平衡/干扰与 token 爆炸；需要平衡 + 稳定性技巧。
- **"统一生成+理解模型如何表示图像？"** 离散码本 token 使图像能与文本一起被自回归生成。
- **"作为视频预训练目标，JEPA 潜在预测 vs 像素/token 生成？"** JEPA 预测表示，忽略不可预测的像素细节，把容量用于动态/语义；它不能生成视频，但能高效迁移到规划（V-JEPA 2-AC）。生成式目标能给出样本和稠密监督，但成本高得多。
- **"文本能力上是否存在'模态税'？"** 历史上存在（干扰）；Qwen3-Omni 报告在 30B-A3B 规模、经过精心配比后不存在——讨论数据配比（data mixture）、容量（MoE 有帮助）以及对纯文本退化的评测。

## 开放问题
统一多模态模型的最佳**表示**（连续 vs 离散）和**融合方式**（早期 vs 后期）仍未定论。**模态平衡**、稳定的大规模早期融合训练、高效的**视频/音频**分词、生成式与潜在预测式目标哪个能产生更好的世界模型，以及单一模型能否在所有模态上匹敌专门的单模态模型，都是开放问题。高质量多模态**数据稀缺**正日益成为制约。
