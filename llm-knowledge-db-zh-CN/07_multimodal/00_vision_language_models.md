# 视觉-语言模型（Vision-Language Models, VLMs）

> **最后更新：** 2026-11-04
> **相关文件：** [多模态预训练](01_multimodal_pretraining.md) · [跨模态对齐](02_cross_modal_alignment.md) · [Transformer 架构](../00_foundations/00_transformer_architecture.md) · [工具使用与函数调用](../04_reasoning_and_agents/03_tool_use_and_function_calling.md)
> **关键论文：** Radford et al. 2021 CLIP（[arXiv:2103.00020](https://arxiv.org/abs/2103.00020)）· Liu et al. 2023 LLaVA（[arXiv:2304.08485](https://arxiv.org/abs/2304.08485)）· Alayrac et al. 2022 Flamingo（[arXiv:2204.14198](https://arxiv.org/abs/2204.14198)）· Dosovitskiy et al. 2020 ViT（[arXiv:2010.11929](https://arxiv.org/abs/2010.11929)）· Tschannen et al. 2025 SigLIP 2（[arXiv:2502.14786](https://arxiv.org/abs/2502.14786)）

## 概述
视觉-语言模型（VLM）让大语言模型（LLM）能够*看见*——在接受文本的同时接受图像（以及越来越多的视频），并对二者联合推理。它们支撑着文档理解、图表/示意图问答、视觉推理、GUI/计算机操作（computer use）智能体以及多模态（multimodal）对话（GPT-4o → GPT-5.x、Gemini 3.x、Claude、LLaVA、Qwen-VL → Qwen3.5）。多年来占主导地位的开放设计出奇地简单：取一个强大的预训练**视觉编码器**和一个强大的预训练 **LLM**，用一个轻量模块把它们**连接**起来，使图像特征变成 LLM 可以关注的"token"。到 2026 年，视觉已成为**旗舰开放 MoE 的原生能力**（Qwen3.5、Kimi K3、DeepSeek V4.1-Flash），而不再是一个单独的"-VL"变体；而要求最高的应用是**计算机操作**——读取截图并据此行动。理解连接器设计（投影 vs 交叉注意力）、对比式与生成式预训练的分野，以及 CLIP/ViT 的作用，是多模态的核心知识。

## 核心概念
**视觉编码器（ViT）。** 图像被切分为图块（patch）（例如 14×14），线性嵌入（embedding）为图块 token 序列，再由**视觉 Transformer（Vision Transformer）**处理。大多数 VLM 使用 **CLIP 预训练的 ViT**（或 SigLIP），因为对比式图文预训练能产出语义对齐、对语言友好的视觉特征。

**CLIP（对比式预训练）。** Radford 等人用**对比（InfoNCE）**损失联合训练图像编码器与文本编码器：在一个包含 $N$ 个图文对的批次中，最大化 $N$ 个正确配对的余弦相似度，最小化 $N^2-N$ 个错误配对的相似度。这得到一个**共享嵌入空间**，支持零样本分类（"a photo of a {class}"），并产生强大的可迁移视觉特征。CLIP 是大多数 VLM 视觉编码器的骨干。

**连接器架构（视觉如何接入 LLM）。**
- **线性/MLP 投影（LLaVA）：** 把 ViT 图块特征投影到 LLM 的 token 嵌入空间，并**作为 token 前置**。极其简单、数据高效、效果出奇地好——最流行的开放方案。
- **交叉注意力（Flamingo）：** 在冻结的 LLM 中插入带门控的**交叉注意力**层，让其关注视觉特征；LLM 基本保持冻结。能处理图文交错输入并扩展到多张图像，但会增加参数/复杂度。
- **重采样器 / Q-Former（BLIP-2）：** 一组可学习的查询 token 对 ViT 特征做交叉注意力，产生**固定且少量**的视觉 token——把大量图块压缩为少数 token（对 LLM 而言更高效）。

**训练阶段。** 通常为：（1）**对齐/预训练**——冻结 ViT 和 LLM，只在图文/字幕数据上训练连接器，使视觉 token "说 LLM 的语言"；（2）**视觉指令微调**——在多模态指令数据（LLaVA-Instruct，通过向文本 LLM 提供图像标注并提示生成）上微调（连接器 + LLM，有时也包括 ViT）。如今许多前沿模型采用**原生多模态预训练**（从零开始联合训练）——见 [多模态预训练](01_multimodal_pretraining.md)。

**视觉 token 预算。** 图块大小为 $p$ 时，一张 $H\times W$ 的图像在池化前产生 $HW/p^2$ 个 token——例如，一张边长 2,576 px 的方形图像在 $p=14$ 时约有 $3.4\times10^4$ 个图块——因此高分辨率截图/文档必须借助池化、配合降采样全局视图的切块，或 token 合并。

## 关键挑战
- **分辨率与 token 预算。** 高分辨率图像产生大量图块 token（成本 ∝ token 数²）；文档/图表理解需要高分辨率。切块/"任意分辨率"（AnyRes）、token 压缩和动态分辨率可以应对。
- **视觉幻觉。** VLM 会描述不存在的物体或误读细节，往往是过度依赖语言先验所致（见 [幻觉](../05_alignment_and_safety/01_hallucination_causes_and_mitigations.md)）。
- **OCR/细粒度感知。** 读取小字、密集图表和精确的空间关系，对 CLIP 式全局特征而言很困难。
- **面向智能体的 GUI 定位。** 计算机操作需要精确定位细小的 UI 元素，并在多张截图之间跟踪多步状态；基准饱和（OSWorld）掩盖了长尾失效。
- **模态鸿沟（modality gap）。** 图像嵌入与文本嵌入在共享空间中占据彼此分离的锥形区域（见 [跨模态对齐](02_cross_modal_alignment.md)）。
- **数据稀缺/质量。** 高质量多模态指令数据比文本更难获取。

## 解决方案与当前最佳实践
**默认的开放配方（连接器式）：** SigLIP/SigLIP 2 ViT + **MLP 投影器** + 强 LLM，配合**任意分辨率切块**、两阶段训练（对齐 → 视觉指令微调）以及**高质量合成指令数据**。使用 **SigLIP**（sigmoid 损失）而非 CLIP 以获得更好的编码器。为提高效率，**压缩视觉 token**（重采样器/池化）。**前沿模型与旗舰开放模型**如今把视觉**原生**训练进基础模型，不过给万亿参数 MoE 配一个小型专用编码器（1–3B 参数）的做法依然常见（Mistral Large 3/4）。对于智能体，在并行虚拟桌面中用强化学习（RL）训练"截图→行动"轨迹。在 MMMU、MathVista、DocVQA、ChartQA、幻觉基准（POPE）上评测，计算机操作则使用 OSWorld-Verified/OSWorld 2.x。

## 各实验室观点
- **OpenAI：** GPT-4V → **GPT-4o**（原生多模态，任意到任意）→ **GPT-5.4**（2026-03），其首个具备**原生计算机操作**的通用模型（截图 + 鼠标/键盘；OSWorld-Verified 75%，厂商数据）；GPT-5.5 为 78.7%。
- **Google DeepMind：** **Gemini** **从预训练起就是原生多模态的**（文本/图像/音频/视频一起训练）——一项关键的架构差异；借助长上下文（long context）理解长视频；自 I/O 2026 起 Gemini 3.5 Flash 成为默认模型；**Gemini Robotics 2**（VLA）和 ER 2（具身推理规划器，据报道基于 3.5 Flash 构建）。
- **Anthropic：** Claude 3+ 的视觉能力侧重文档/图表/示意图理解与安全的视觉推理；Opus 4.7（2026-04）把图像输入提高到 2,576 px；Opus 5.5 在 OSWorld 2.1 上得分 81.8%（部分得分制，厂商数据）；Haiku 5.5 在 SDK 中增加了 beta 版计算机/浏览器操作。
- **Meta：** Llama 3.2 Vision（在 Llama 上加交叉注意力适配器（adapter））；其闭源的 **Muse Spark**（2026-04）声称在多模态理解上最强（厂商声明）。
- **开放社区/学术界：** LLaVA（投影器范式）、Qwen-VL/InternVL（强大的开放 VLM）、BLIP-2（Q-Former）；2026 年具备原生视觉的旗舰模型：Qwen3.5-397B-A17B、Kimi K3、DeepSeek V4.1-Flash、MiMo-V2.5、Gemma 4。

## 最新进展（2023–2026年11月）
**原生多模态、任意到任意**模型（GPT-4o、Gemini）在一个模型中处理文本/图像/音频/视频，并能跨模态*生成*。**任意分辨率**与动态 token 分配改进了文档/OCR/图表任务。借助长上下文实现**视频**理解（Gemini）。**面向智能体的视觉**——感知截图并采取行动的 GUI/计算机操作模型。**SigLIP/SigLIP2** 取代 CLIP 成为首选编码器。持续聚焦于减少**视觉幻觉**和提升细粒度感知。

**2025年中 → 2026年11月更新：**
- **视觉并入旗舰开放 MoE（2026-02 → 2026-09）。** Qwen3.5-397B-A17B（2026-02，Apache 2.0）是原生视觉-语言模型；Kimi K3（2026-07；总参数 2.8T / 激活 104B，KDA:MLA 为 3:1 的混合结构）以 1M 上下文附带原生视觉；DeepSeek **V4.1-Flash**（2026-09，552B MoE，输入文本+图像、输出文本，MIT 许可）同时取代了 V4-Flash 和实验性的 V4-Flash-Vision——在最高端，单独的"-VL"模型线正在消失。
- **……但连接器在万亿规模上依然存在。** Mistral Large 3（2025-12；675B/41B）使用 2.5B 的视觉编码器，Mistral Large 4（2026-10；约 1.05T/52B）使用 1.6B 的编码器——远低于参数总量的 1%——表明当语言模型足够大时，编码器+投影器设计仍具竞争力。
- **托管版 ≠ 开放检查点。** Qwen3.8 的开放权重（2026-08，2.4T/95B）仅支持文本，而托管的 Qwen3.8-Max-Preview 是多模态的；"开放"模型的使用者必须核实实际发布了哪些模态。
- **计算机操作成为头部能力（2026-03 → 2026-09）。** GPT-5.4 使原生计算机操作普及到通用模型；到 2026-04，OSWorld-Verified 达到约 78–79%（GPT-5.5、Opus 4.7），而原始划分上的人类基线约为 72%，于是各实验室转向带部分得分的 OSWorld 2.x（Opus 5.5 81.8%；Haiku 5.5 在离线子集上 72.4%——厂商数据）。在数千个并行虚拟桌面上进行的智能体式强化学习（ComputerRL，arXiv:2508.14040）推动了开放社区的这些进展。
- **更高的原生分辨率。** Opus 4.7 接受最高 2,576 px 的图像，这反映了密集截图和文档类工作负载的需求——降采样会毁掉其中的小字。
- **端侧多模态。** Gemma 4（2026-04，Apache 2.0）的 E2B/E4B 端侧模型使用逐层嵌入，可接收文本、图像和音频，上下文 128K；MiMo-V2.5（2026-04，MIT）在约 310.8B/15B 激活的规模上增加了原生视觉与音频，上下文 1M。
- **视觉-语言-动作（VLA）。** Gemini Robotics 2（2026-07）是用于全身人形机器人控制的 VLA，配合 ER 2 规划器以及多机器人任务拆分（二手报道）。

## 面试要点
> 💡 **实验室实际会问的问题：**
- **"CLIP 如何工作？为什么用作 VLM 编码器？"** 在图文对上做对比式 InfoNCE → 共享且与语言对齐的嵌入空间；其特征能很好地迁移到 LLM 连接器。
- **"投影式与交叉注意力式连接器——如何权衡？"** 投影（LLaVA）：简单、数据高效，所有视觉 token 进入序列；交叉注意力（Flamingo）：保持 LLM 冻结，可扩展到多张图像，但更复杂。
- **"VLM 为什么会产生视觉幻觉？"** 过度依赖语言先验、细粒度感知薄弱、分辨率低。
- **"如何处理高分辨率图像？"** 切块/任意分辨率 + 视觉 token 压缩（重采样器/池化）；计算 token 数 $HW/p^2$ 以及注意力的平方级开销。
- **"原生多模态 vs 外挂编码器——Gemini 为何不同？"** 联合预训练带来更紧密的跨模态融合和生成能力，而非连接预训练好的单模态模型。
- **"为什么实验室会给一个 1T 参数的 MoE 配一个 1.6B 的视觉编码器，而不是原生训练视觉？"** 复用强大的预训练编码器，解耦视觉与语言模型的训练进度，使文本预训练保持低成本和稳定；代价是融合较松散且没有原生图像生成。
- **"计算机操作为什么比 VQA 更难？"** 细小目标的定位、跨多张截图的长程状态跟踪、动作空间设计（API vs GUI），以及需要在交互环境中做强化学习而非静态监督。

## 开放问题
鲁棒的**细粒度感知**（OCR、密集图表、精确的空间/时间推理）、消除**视觉幻觉**、高效处理**高分辨率与长视频**、在长时间智能体会话中实现可靠的 **GUI 定位**，以及真正统一的**任意到任意**理解+生成，都是开放问题。究竟是从零构建原生多模态，还是连接强大的单模态模型，仍是一场悬而未决的架构之争——2026 年的旗舰模型两种做法都有。
