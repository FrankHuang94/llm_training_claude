# 智能体框架（Agentic Frameworks）

## 概述
**智能体（agent）**是被置于循环中的大语言模型（LLM）：它感知状态、进行推理、采取行动（工具调用）、观察结果，并在尽量少的人类干预下朝目标迭代。智能体框架（LangChain/LangGraph、AutoGen、CrewAI、LlamaIndex、OpenAI Agents SDK、Claude Agent SDK、smolagents）提供脚手架——控制循环、记忆、工具集成、规划和编排——把一个对话模型变成目标导向的系统。2023年的"AutoGPT/BabyAGI"浪潮承诺过度；2024–2026年的现实更为克制：智能体如今在**受约束的、可验证的、工具丰富的领域**（编程、研究、客户支持）中表现良好，并且是各实验室的主要商业重心。到2026年底，前沿智能体能够连续数小时保持连贯工作（厂商报告了18–30+小时的会话），前沿模型的METR 50%时间跨度超过约16小时，而评测/运行框架已经变薄为围绕模型的一个通用循环——模型的智能体能力主要存在于权重之中。

## 核心概念
**智能体循环。** 核心组件：(1) **规划**（分解目标、决定下一步行动），(2) **行动/工具执行**，(3) 摄取**观察/反馈**，(4) **记忆**（跨步骤的状态），迭代直到终止。ReAct是最小的循环；更丰富的框架会加入显式规划器和状态机。

**规划模式。** *ReAct*（推理与行动交替）、*Plan-and-Execute*（先制定完整计划，再逐步执行——更适合长时程）、在行动上做*树/图搜索*，以及*分层*规划（高层规划器+低层执行器）。LangGraph及类似框架把智能体建模为**图/状态机**以提升可控性。

**记忆。** 智能体需要超出上下文窗口（context window）的记忆：**短期**（草稿区、对话）、**长期**（对过往经验的向量库检索）以及**情景/程序性**（习得的技能）。MemGPT式的"虚拟上下文管理"把信息换入/换出（见[长上下文与记忆](../09_emerging_frontiers/00_long_context_and_memory.md)）。在2026年，记忆操作越来越多地成为用RL训练出的*习得*工具动作。

**上下文工程。** 长时间运行会超出任何上下文窗口，且质量会随上下文填满而下降（"上下文腐化（context rot）"）。标准工具箱：**压缩（compaction）**（总结并重启窗口）、写入文件的**结构化笔记**、通过工具进行**即时检索**，以及拥有干净上下文、返回浓缩结果的**子智能体**。

**反思/自我纠错。** *Reflexion*（Shinn et al.）：一次尝试失败后，智能体**用语言反思**哪里出了错，把反思存入记忆再重试——无需权重更新即可在任务内学习。这是提升可靠性的强大模式。

**技能习得。** *Voyager*（Minecraft）：一个编写、测试并把可复用代码"技能"存入不断增长的技能库的智能体，展现出开放式的自我改进——这是终身智能体学习的一个有影响力的示范。Agent Skills（SKILL.md文件夹，2025）把同一思想产品化，用于通用智能体。

**时间跨度。** METR通过在一组计时任务上拟合$P(\text{success})=\sigma\big(\alpha-\beta\log t\big)$，来衡量智能体以50%概率成功时对应的人类任务时长$t$；时间跨度即拟合曲线穿过0.5的位置。

## 关键挑战
- **误差累积/脆弱性。** 长时程任务之所以失败，是因为每步错误率会累积；一个可靠度95%的步骤重复20步，成功率≈36%。可靠性是核心障碍。
- **规划与长时程连贯性。** 模型难以提前规划多步、从偏离轨道的状态恢复并保持目标一致。
- **记忆管理。** 决定存储/检索/遗忘什么；上下文膨胀与信息丢失之间的取舍。
- **评测（evaluation）。** 智能体基准噪声大、依赖环境，且很快饱和或被污染（contamination）；可复现性差。厂商的脚手架得分可能比标准化脚手架高10–30分。
- **成本与延迟。** 大模型的多步循环昂贵且缓慢。
- **安全。** 自主行动放大了风险（不安全操作、提示注入（prompt injection）、失控循环）；2026年出现了因智能体意外获得互联网访问而导致的真实事件。

## 解决方案与当前最佳实践
**约束领域并使用可验证的反馈**（代码执行、环境奖励）——智能体在行动可检查的地方表现出色。对产品而言，优先选择**显式、可控的编排**（状态机/图，LangGraph），而非完全自主的"什么都做"循环；对前沿编程智能体，则在RL训练的模型外面使用一个**薄的通用框架**（bash、文件编辑、搜索、子智能体）。加入**反思/重试**、**结构化记忆+检索**、**压缩**以及**护栏**（权限、沙箱、高风险操作的人在回路、在执行前筛查行动的在线监控器）。越来越多地用基于执行奖励的RL对智能体进行端到端**训练**，从而得到更鲁棒的行为。在真实的、有版本管理的基准（SWE-bench Pro、Terminal-Bench、τ-bench、WebArena、GAIA、OSWorld）上，使用标准化框架进行评测。

## 各实验室观点
- **OpenAI：** Agents SDK、Operator/计算机操作（computer use）、"Deep Research"智能体、Codex；GPT-5.4原生计算机操作；GPT-6 Astra的提升部分归因于长时程RL。
- **Anthropic：** Claude Code与**Claude Agent SDK**（2025-09，把Claude Code的运行框架开放给通用智能体）、MCP与Agent Skills、上下文压缩和智能体团队（2026-02）；Haiku 5.5被定位为子智能体/压缩模型；重视智能体安全与监控。
- **Google DeepMind：** Gemini智能体、Project Mariner（网页）、**Antigravity**（2025-11，一个以智能体为先的IDE，也可运行Claude和gpt-oss智能体）、Gemini Spark持久智能体（2026-05宣布）。
- **开放生态：** LangChain/LangGraph、Microsoft AutoGen、CrewAI、HuggingFace smolagents提供框架层；开放智能体模型（Qwen-Agent、GLM、Kimi）。

## 最新进展（2023–2026年11月）
领域从**提示编排**的智能体（LangChain风格）转向**RL训练**的智能体式模型，能力存在于权重中，框架只提供更薄的编排。**编程智能体**（SWE-bench分数急剧上升）和**深度研究/网页智能体**成为旗舰产品。**计算机操作**（通过截图控制GUI）出现。**MCP**实现了标准化。高度关注**可靠性**（减少误差累积）和**长时程**能力，这是关键前沿。

**2025年中 → 2026年11月更新：**
- **时间跨度持续翻倍（2025-03 → 2026）。** METR的50%时间跨度在2019–2025年间约每7个月翻一番（[arXiv:2503.14499](https://arxiv.org/abs/2503.14499)）；TH1.1更新（2026-01）把2023年后的翻倍时间定为约4.3个月（二手总结）。对早期Claude Mythos Preview快照的测量为"至少16小时（95%置信区间8.5–55小时）"；METR表示其任务集在约16小时以上已接近饱和。
- **数小时自主运行的说法（2025-09 → 2026-09）。** Sonnet 4.5在多步任务上保持专注超过30小时；一位测试者让Opus 5.5自主运行了超过18小时（厂商自报）。
- **运行框架变成SDK（2025-09 → 11）。** Claude Agent SDK开放了Claude Code的运行框架；Google Antigravity作为多厂商智能体IDE与Gemini 3一同发布。
- **上下文压缩与记忆（2025-09 → 2026-02）。** Anthropic的上下文工程指南（压缩、笔记、子智能体）变成了产品功能（Opus 4.6中的压缩beta）；AgeMem把记忆操作训练成由RL学习的工具动作（[arXiv:2601.01885](https://arxiv.org/abs/2601.01885)）；Memory-R1从约150个问答对中学会ADD/UPDATE/DELETE/NOOP。
- **面向智能体式RL的环境规模化（2026）。** SWE-Master（[arXiv:2602.03411](https://arxiv.org/abs/2602.03411)）、带框架随机化的KAT-Coder-V2.5（[arXiv:2607.05471](https://arxiv.org/abs/2607.05471)）以及CodeMidas（[arXiv:2609.22068](https://arxiv.org/abs/2609.22068)）合成可验证环境——这如今是主要瓶颈。
- **基准更替（2026）。** OpenAI在发现被审计的难题中≥59.4%的测试有缺陷且存在污染后，停止报告SWE-bench Verified（2026-02）；Terminal-Bench在约一年内从2.0升级到4.0。
- **规模化的智能体需要监控（2026-08）。** Anthropic报告内部约有3万个并发智能体，所有行动在执行前都经过在线监控器（2026年8月超过10亿次决策中有0.002%被拦截）。

## 面试要点
> 💡 **实验室实际会问的问题：**
- **"描述一个LLM智能体的组成部分。"** 规划、工具/行动执行、观察、记忆，在带终止条件的循环中运行。
- **"长时程智能体为什么会失败，如何提升可靠性？"** 每步误差累积；可验证反馈、反思/重试、限定范围、更好的规划、RL训练。
- **"什么是Reflexion？"** 对失败进行语言反思并存入记忆，以在无需权重更新的情况下改进后续尝试。
- **"提示编排与训练出的智能体——如何权衡？"** 框架灵活但脆弱；RL训练的智能体更鲁棒，但构建成本高。
- **"在上下文有限的情况下，如何让一次20小时的智能体运行保持连贯？"** 压缩、外部笔记/文件、即时检索、拥有干净上下文的子智能体、周期性自我验证；用时间跨度式评测来衡量。

## 开放问题
**可靠的长时程自主**是最具决定性的未解问题——稳健的规划、错误恢复以及多步之上的目标一致性。有效的开放式**记忆/持续学习（continual learning）**、可信的**智能体评测**（随着时间跨度任务集饱和）以及**安全自主**（在对抗条件下防止有害行动）都很活跃，且基本未解决。
