# 投机解码（Speculative Decoding）

> **最后更新：** 2026-11-04
> **相关文件：** [知识蒸馏](03_knowledge_distillation.md) · [注意力机制](../00_foundations/01_attention_mechanisms.md) · [量化技术](02_quantization_techniques.md)
> **关键论文：** Leviathan et al. 2023 Speculative Decoding（[arXiv:2211.17192](https://arxiv.org/abs/2211.17192)）· Chen et al. 2023 Speculative Sampling（DeepMind）（[arXiv:2302.01318](https://arxiv.org/abs/2302.01318)）· Cai et al. 2024 Medusa（[arXiv:2401.10774](https://arxiv.org/abs/2401.10774)）· Li et al. 2024 EAGLE（[arXiv:2401.15077](https://arxiv.org/abs/2401.15077)）· Li et al. 2025 EAGLE-3（[arXiv:2503.01840](https://arxiv.org/abs/2503.01840)）

## 概述
自回归解码本质上是**串行且受内存带宽限制**的：每个 token 都需要一次读取全部模型权重的完整前向计算，却只轻度使用 GPU 的算力（批大小为 1）。投机解码（speculative decoding）利用一个关键的不对称性打破了这一瓶颈：并行**验证**若干候选 token 的成本几乎与生成一个 token 相同（两者都是一次前向计算，而这次计算受带宽限制，因此一次处理 $k$ 个 token 的代价与处理一个几乎相同）。一个小的**草稿**模型提出若干 token；大的**目标**模型在一次并行计算中验证它们；被接受的 token 予以保留。关键在于，这能带来 **1.5–3 倍的加速（使用现代草稿器时更高），且输出分布*完全相同***——一种无损加速，这正是它被到处部署的原因。长推理输出和智能体工作负载让它变得更有价值，而不是相反。

## 核心概念
**先草拟、后验证的循环。**
1. 一个廉价的**草稿**模型自回归地提出 $\gamma$ 个候选 token $\hat x_{1..\gamma}$。
2. **目标**模型对全部 $\gamma$ 个候选并行地运行**一次前向计算**，得到每个位置上的真实分布 $p(x_i\mid \cdot)$。
3. **验证 / 接受：**以一个能保证最终样本*完全*服从目标模型分布的概率接受每个草拟的 token。在第一次拒绝时，从校正后的残差分布中**重新采样**该 token，并丢弃其余部分。

**为什么是精确的（拒绝采样）。** 对于草稿分布 $q$ 和目标分布 $p$，以概率 $\min(1, p(x)/q(x))$ 接受 token $x$；被拒绝时，从归一化的残差 $(p-q)_+$ 中采样。这种**修正的拒绝采样**可以证明产生来自 $p$ 的样本——加速在期望意义上是"免费"（无损）的。每步期望接受的 token 数取决于 $q$ 对 $p$ 的近似程度（**接受率**）；草稿越对齐，加速越大。贪心解码是一个特例：当草稿与目标的 argmax 相同时就接受。

**变体（去掉/改进草稿模型）。**
- **自草拟 / Medusa**（Cai et al.）：不使用单独的草稿模型，而是给目标模型加上多个**额外的解码头**，一次预测多个未来 token；用树状注意力进行验证。无需额外训练/服务一个单独模型；与基座融为一体。
- **EAGLE**（Li et al.）：在**特征（隐藏状态）层面**用一个轻量的自回归头做草拟，获得高接受率和大幅加速；EAGLE-2 增加了动态草稿树。**EAGLE-3** 放弃了特征回归，改为直接预测 token，融合目标模型低/中/高层特征，并以"训练时测试（training-time test）"（模拟多步草拟）进行训练——当前最先进的方法之一。
- **Lookahead 解码**（Fu et al.）：无需草稿；利用 Jacobi/n-gram 并行性生成并验证 n-gram。
- **树状/批量验证（SpecInfer）：**验证一*棵*候选续写树，以提高每步接受的 token 数。
- **自投机 / 跳层：**用模型自身的一部分层作为草稿。

**与多 token 预测的协同。** 用 **MTP 头**训练的模型（DeepSeek-V3，以及如今的 Qwen3-Next、GLM-4.5/5）自带草拟机制——预训练与推断加速协同设计（见[模型架构变体](../00_foundations/05_model_architecture_variants.md)）。

## 关键挑战
- **草稿–目标对齐。** 接受率低（草稿差）会让加速化为乌有；草稿必须在实际负载上很好地匹配目标分布。
- **草稿模型的成本/训练。** 单独的草稿模型会增加内存，而且必须训练/蒸馏并与目标保持同步。
- **批处理的矛盾。** 投机解码在**小批量**（受延迟、带宽限制）时帮助最大；在**大批量**（受吞吐限制、算力饱和）时，并行验证的优势缩小，甚至可能有害。
- **树/验证开销。** 树状验证提高了接受率，但增加了计算量和复杂度。
- **接受率波动。** 困难/不确定的区域（推理、罕见 token）接受率较低。
- **有状态的架构。** 在线性注意力/SSM 混合架构中，被拒绝的 token 已经更新了递推状态，因此验证需要状态检查点或重计算，而不能像 KV 那样简单截断。

## 解决方案与当前最佳实践
在延迟敏感的服务中，使用 **EAGLE-3、原生 MTP 头或 Medusa** 进行自草拟（无需单独模型）；有同族的**蒸馏小草稿模型**时效果也很好。用**更多数据**训练草稿器——在 EAGLE-3 下，加速会随草稿训练数据持续增长。根据接受率调优**草稿长度 $\gamma$**（接受率高时更长的草稿有益）。通过实现了投机解码 + 树状验证的推断引擎（vLLM、TensorRT-LLM、SGLang）部署。与**量化**（量化后的目标模型）和**连续批处理**结合；在投机得不偿失的大批量下禁用或调整投机。对于输出很长的推理模型，投机解码尤其有价值（长序列放大了每 token 的节省）。

## 各实验室观点
- **Google DeepMind/Google**（Leviathan、Chen）提出了投机解码/投机采样，在服务中被广泛使用；还预览了 **Gemini Diffusion**（2025-05），一种并行生成的替代方案。
- **OpenAI/Anthropic：**在生产服务中使用投机式加速（细节保密）；"predicted outputs"功能类似于投机验证。OpenAI 还追求原生低延迟硬件（GPT-5.3-Codex-Spark 运行在 Cerebras WSE-3 上，超过 1,000 tok/s）。
- **DeepSeek：**以 **MTP** 训练的模型提供原生草稿头（V3）——预训练与推断加速协同设计；**Qwen** 和**智谱**采用了同样的 MTP 模块。
- **开源生态：**Medusa、EAGLE(-3)、vLLM/TensorRT-LLM/SGLang 广泛提供投机解码。
- **Inception Labs / inclusionAI：**押注**扩散语言模型**，它们原生地每步解码多个 token。

## 最新进展（2023–2026年11月）
**EAGLE-2/3** 和动态**草稿树**在有利场景下把加速推高到约 3–5 倍。**自草拟**（Medusa/EAGLE）免去了单独草稿模型的负担。**以 MTP 为草稿**的协同设计（DeepSeek-V3）把训练目标与推断加速联系起来。活跃的研究方向包括**大批量**投机解码、面向**推理/长输出**模型的投机，以及把投机与量化和解耦式（预填充/解码分离）服务相结合。

**2025年中 → 2026年11月更新：**
- **EAGLE-3（2025-03，NeurIPS 2025）。** 去掉特征回归约束、直接预测 token，配合多层特征融合和训练时测试，使加速**随草稿训练数据增长**：加速最高 6.5 倍，在 SGLang 中即便批大小为 64 也有 1.38 倍的吞吐提升——证明投机在中等批大小下也能有收益（[arXiv:2503.01840](https://arxiv.org/abs/2503.01840)）。
- **MTP 模块成为默认草稿（2025–26）。** DeepSeek-V3 式的 MTP 模块已在 Qwen3-Next 和 GLM-4.5/5 中落地，既用作训练信号，也用作原生的投机草稿——无需单独训练草稿器或保持同步。
- **通过自蒸馏加装 MTP（2026-02）。** 把预训练的 NTP 模型转换为独立的 MTP 解码器，报告在 GSM8K 上解码加速超过 3 倍、准确率损失低于 5%（[arXiv:2602.06019](https://arxiv.org/abs/2602.06019)）——注意这是*有损*的，不同于经过验证的投机。
- **扩散语言模型作为"无草稿"替代方案（2025-06 → 2026-02）。** Mercury 每步预测多个 token（[arXiv:2506.17298](https://arxiv.org/abs/2506.17298)）；Mercury 2 声称在 Blackwell 上约 1,000 tok/s（自报）；LLaDA2.0 加入置信度损失，在 100B 规模上实现激进的并行解码（[arXiv:2512.15745](https://arxiv.org/abs/2512.15745)）。
- **服务架构的转变（2025-09 → 2026-05）。** 预填充/解码解耦（NVIDIA Rubin CPX 负责预填充）以及面向 MoE 的注意力–FFN 解耦（[arXiv:2605.28302](https://arxiv.org/abs/2605.28302)）改变了验证计算所在的位置；投机必须与这些拆分协同设计。

## 面试要点
> 💡 **实验室实际会问的问题：**
- **"为什么投机解码能加速推断而不改变输出？"** 解码受带宽限制；在一次并行计算中验证 $k$ 个 token ≈ 一个 token 的成本；修正的拒绝采样保证目标分布 → 无损。
- **"解释接受/验证步骤。"** 以 $\min(1,p/q)$ 接受；被拒绝时从 $(p-q)_+$ 重新采样——可证明是从目标 $p$ 中采样。
- **"加速比由什么决定？"** 接受率（草稿–目标对齐）× 草稿长度，减去开销。
- **"Medusa/EAGLE 与单独的草稿模型相比如何？"** 自草拟的头/特征免去了单独模型并提高了接受率。
- **"投机解码什么时候不起作用？"** 大批量/计算受限的场景；草稿对齐差。
- **"EAGLE-3 改变了什么，为什么它现在能随数据扩展？"** 特征回归损失把草稿器束缚在模仿隐藏状态上；改为从融合的多层特征直接预测 token，并以模拟多步草拟的方式训练，消除了这一瓶颈，使更多草稿数据能持续提升接受率。

## 开放问题
在多样化且**推理密集**的负载上最大化接受率（更好且廉价的草稿）、让投机解码在**大批量**下也有收益、面向**递推/混合**架构的投机，以及训练（MTP）与推断投机的最优协同设计，都是开放问题。扩散或其他并行解码器能否达到自回归质量——从而使投机变得不再必要——以及在本质上串行的生成中多 token 并行的理论极限，仍是有趣的问题。
